Building an Interactive Column Interaction Diagram in the Browser

A working ACI 318-19 P-M interaction diagram tool, built from scratch as a single HTML file. Here's what's inside, why each piece works the way it does, and what I'd improve next.

Most online column interaction diagram tools are one of three things: a clunky Excel download, a paywalled feature inside a $2,000/yr design suite, or a static PDF chart from a textbook appendix. None of them let you actually play with the section — change the cover, swap the bar size, push a different demand point — and watch the curve respond in real time. So I built one.

The result is a single-page tool that runs entirely in your browser: column-interaction.html. No login, no install, no upload to a server. You change a number, the diagram redraws, and you can see whether your section passes the moment you type.

This post walks through how it works — the engineering, the code structure, and the trade-offs. It's aimed at engineers who are curious about what's behind the screen, and at developers who want to see how a small but real engineering tool gets built.

The engineering, briefly

A reinforced concrete column's capacity isn't a single number — it's a curve in (P, M) space. Push more axial load and the section can carry less moment. Push more moment and it can carry less axial. The interaction diagram traces the boundary of that envelope.

Per ACI 318-19, you trace the boundary by sweeping a single parameter: c, the depth of the neutral axis from the extreme compression fiber. For each value of c:

  1. Assume the extreme compression fiber strain is at its ultimate, εcu = 0.003.
  2. Compute strain at every reinforcement layer using strain compatibility (linear strain distribution).
  3. Convert each layer's strain to stress, capped at ±fy.
  4. Add up the concrete compression block force (Whitney rectangular block) and all the steel forces.
  5. Take moments about the plastic centroid.

That gives you one (Pn, Mn) point. Sweep c from a very large value (pure compression) down to zero (pure tension) and you've drawn the entire nominal envelope.

Pn = 0.85 f'c · b · a + Σ Asi · fsi
Mn = 0.85 f'c · b · a · (h/2 − a/2) + Σ Asi · fsi · (h/2 − di)

For the design envelope (φPn, φMn), each point gets a strength reduction factor based on the strain in the extreme tension steel:

  • Tension-controlled (εt ≥ 0.005): φ = 0.90
  • Compression-controlled (εt ≤ εty): φ = 0.65 for tied sections
  • Transition zone in between: linear interpolation

And for tied columns, ACI caps the maximum design axial: φPn,max = 0.80 × φ × P0. This shows up as a flat plateau across the top of the design curve. It's a recognition that even a "pure compression" column will have some accidental eccentricity in practice.

Translating it to code

The whole tool is a single HTML file with maybe 250 lines of JavaScript. The core is a function that takes a value of c and returns the corresponding (Pn, Mn):

function computePnMn(c, b, h, fc, fy, layers) {
    const a = Math.min(beta1(fc) * c, h);
    const Cc = 0.85 * fc * b * a;

    let Fs = 0, Ms = 0, eps_t = -1;
    layers.forEach(layer => {
        const eps_s = 0.003 * (c - layer.d) / c;
        let fs = Math.max(Math.min(Es * eps_s, fy), -fy);
        const f_eff = (layer.d <= a) ? fs - 0.85 * fc : fs;
        Fs += layer.As * f_eff;
        Ms += layer.As * f_eff * (h/2 - layer.d);
        if (-eps_s > eps_t) eps_t = -eps_s;
    });

    return { Pn: Cc + Fs, Mn: Cc * (h/2 - a/2) + Ms, eps_t, c };
}

That's it. The whole strain compatibility loop fits in eleven lines because forEach handles iterating across reinforcement layers and arithmetic is just arithmetic. The little f_eff trick subtracts the 0.85 f'c contribution from the gross concrete area when a bar sits inside the compression block — otherwise you'd double-count that concrete.

To trace the envelope, the tool calls computePnMn at ~80 values of c, logarithmically spaced (so we get more resolution near the balanced point and less in the flat compression-controlled region). Plus two endpoints: pure compression at c → ∞, and pure tension at c = 0.

The most useful trick I learned: spacing your samples logarithmically, not uniformly. Linear c-spacing gives you a beautiful pure-compression cap and a horrible balanced-point corner. Log-spacing flips that, which is exactly what you want — the interesting action is near the transition.

Drawing it

The diagram itself is SVG, not Canvas, not a charting library. SVG is the right choice here for two reasons: it's vector, so it stays crisp at any zoom, and it's just XML, so JavaScript can build the whole picture as a string and assign it to innerHTML in one shot. No animation framework, no D3, no Chart.js — none of it is needed for a static curve.

The drawing function takes the array of computed points and maps each (P, M) value to an SVG (x, y) coordinate using a tiny pair of helpers:

const toSvgX = M => margin.left + (M / M_axis) * plotW;
const toSvgY = P => margin.top + plotH
                  - ((P - P_min) / (P_max - P_min)) * plotH;

Then the path string is built by walking the points: M x y L x y L x y …. SVG's path syntax is the simplest possible drawing language — "move here, then draw a line to here, then a line to here." Each call to generate() rebuilds the entire SVG and replaces the old one. Cheap, simple, and fast enough that you can't even see it happen.

The axes auto-scale using a small niceUp() helper that rounds an axis maximum up to the nearest 1, 2, 5, or 10 × 10n. Without it, the axis labels would say things like "1683 kip" — with it, they snap to "2000 kip" and the diagram always reads cleanly.

What I'd build next

This is a v1. Honest list of what's missing:

  • Multiple bar layers. Right now I only model bars on the two extreme faces. Real columns often have intermediate side bars, especially in larger sections. Adding a third layer is a 5-line change.
  • Biaxial bending. The current tool computes the 2D P-M curve about one axis. The full biaxial interaction surface is a 3D shape. A meaningful upgrade — probably a 2-week project to do well.
  • Slenderness. No second-order effects. Adding a sidebar that computes slenderness ratio and applies the moment magnification per ACI Chapter 6 is the natural next addition.
  • Code toggle. Right now it's ACI 318-19 only. IS 456 (Indian code) uses different φ factors and a different stress-block shape — switching codes would mean a small refactor of the strength reduction and stress-block functions.
  • Hover-to-inspect. Hover any point on the curve and see (P, M, c, εt, controlling failure mode). Pure UX polish but it's what would turn the tool from "useful for a quick check" into "useful for actually understanding a section."

None of these are fundamentally hard. They're all evolutions of the same strain-compatibility loop and the same SVG drawing pattern. Which is the bigger lesson: once you have a working core, a real engineering tool grows by addition, not by replacement.
